# 首轮代码检测（2026-09-11）

范围：静态检查聊天、记忆、配置、动作生成及行为调度；执行 `swift build --quiet`，退出码 0，仅有 AppDelegate 中 Selector 构造方式的警告。没有启动应用、调用模型 API 或执行 UI/回归测试。下列为代码路径确认的问题，尚未做运行时复现；本轮不修改业务代码。

## 待修问题

1. **P1：自动记忆解析可能使应用崩溃。** `ChatSession.swift:82–85` 只检查方括号存在，没有检查起止索引顺序。模型返回 `][` 等异常文本时，`s...e` 构造非法范围，触发运行时 trap，`try?` 无法捕获。应先验证 `s <= e` 或改为安全 JSON 解析。
2. **P1：隐身模式仍观察并向模型发送前台应用名。** `AppDelegate.swift:51–59` 的聊天和摸头提示词只检查 `senseFrontApp`，未检查 `stealth`；`updateBehaviorAction` 也继续查询前台应用和空闲状态。设置页承诺“暂停观察”。当开启隐身、保留默认前台感知，并在其他应用前台时和宠物互动，仍可能携带应用名。需要统一隐私开关的生效边界。
3. **P1：清空数据或关闭自动记忆后，后台结果仍会写回。** `ChatSession.clear()` 只清数组，未取消/作废聊天与记忆 Task。聊天完成后仍追加并落盘；记忆提取完成处也没有重新检查隐身、自动记忆开关或清空代次。发送后清空全部数据，或提取期间清空记忆/关闭自动记忆，可能出现内容重新生成。需要任务取消和结果代次校验。
4. **P2：前台有应用时，久闲睡眠分支不可达。** `AppDelegate.swift:295–297` 先判断 `frontActive`，再判断 `idleLong`。普通应用保持前台但用户离开超过 180 秒时，仍选择 work。应让空闲判定优先。内置 sleep 缺帧是另一个既有边界，验证时需有 sleep 动作帧。
5. **P2：批量生成途中切换形象，会把后续动作生成给新形象。** `AppState.generateAllActions()` 只固定动作列表，每次 `generateActionDef()` 重新读取当前 `config.character` 和参考图；`PetSettingsCards.swift:226` 允许切换。A 形象生成第一项时切到 B，剩余项将使用 B，造成 A 不完整、B 动作意外生成/覆盖并消费 API。应在批次开始固定形象与参考图，或阻止中途切换。

优先建议：先修崩溃及隐私/清空语义，再修行为与批量生成。修复需用户另行指定；本报告不代表全面验收通过。
